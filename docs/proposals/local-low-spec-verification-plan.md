# 本地低档机（NAS / Intel G7400 + UHD 710）验证计划（2026-10-04）

> 目的：用零租用成本的本地机器承担"三端速度对比 + 低档 GPU 回退档 + 跨机确定性"三件事，
> 从而把租用预算留给第三方真值（正确性）与匹配硬件（外部可比性）两类必须花钱的用途。

## 一、可行性结论（先回答"可不可行"）

**可行。** 三条判断：

1. **2 核（G7400 = 2C/4T）足以跑出三端差异**——依据：我们的三端是"同一算法、三种语言实现"，
   差距是**数量级**而非百分比（实测 `sequence.stats.v1`：rust 30 ms / python 270 ms / r 1770 ms ≈ 59×）。
   2 核只影响绝对时长与调度噪声，不改变数量级差。**纪律**：输入放大到 ≥100 ms 量级、每档 ≥3 次取中位、
   同时报 min/max/IQR；个位数毫秒的用例在小机上不可作结论。
2. **"我们自己的 GPU 能跑"= 能，但定位是回退档**。G7400 的核显是 **Intel UHD 710**（Xe-LP 级、16 EU、
   支持 Vulkan 1.2/1.3），走 wgpu/Vulkan 可运行我们的 WGSL 内核（f32/u32 口径正合适）。
   预期性能很低（无矩阵引擎、与 CPU 共享内存带宽）——价值在**"最低档能跑则向上皆稳"**与回退路径验证，
   不在性能数字。风险：headless 环境需先确认 Vulkan ICD 与 DRM 渲染节点（我们在 vGPU/S4000 上已踩过同类坑）。
3. **外部对比必须匹配硬件或披露硬件**。第三方平台（PTS/OpenBenchmarking）的结果页会记录完整系统
   （CPU 型号/核数/内存/GPU/内核/发行版）。因此三条路线：
   - **同机三端对比**（我们完全可控，无需匹配）→ 速度叙事的主力；
   - **发布自有 test profile**（他人可在自己机器上跑，结果带硬件信息，跨机可比）→ 外部可比性的正路；
   - **租匹配硬件**（只有需要"同配置横向"时才花钱）。

## 二、机器角色与分工

| 维度 | 谁来产出 | 本机（NAS/G7400）角色 |
| --- | --- | --- |
| **正确性** | 第三方真值（GIAB + hap.py）、第三方流程对照（nf-core） | 无关（正确性与硬件无关） |
| **速度（相对）** | 我们自己的三端实现（rust/python/r） | **主力参照机**：零成本、随时可跑、同机可控 |
| **速度（绝对/跨机）** | 分档记录（低端核显 → 独显 → 数据中心） | **最低档锚点**：UHD 710 核显与 GTX 750 Ti 独显两个数据点（实测本机有两块 GPU） |
| **确定性（跨机复现）** | 种子化能力（模拟器/SSR/对接等） | **新增一个跨机数据点**（与云租机器比对） |
| **外部横向** | PTS profile + 匹配硬件 | 只作 profile 的"最低配置"验证机 |

## 五、纪律

- Linux 为唯一正式工况；小机数据同样要记硬件与线程数。
- 低端数据只用于**相对比较与回退验证**，不得包装成绝对性能结论。
- 三端对比的口径固定：固定输入 + 固定种子 + 同机 + 每档 3 次取中位。
