# 测量精度与重复轮次方案（2026-10-04 窗口，待评审）

> 背景：已有 7 条三端数据用的是 `--repeat 3`（预热 1 次 + 计时 3 次），单轮采样。
> 其中 `sequence.stats.v1` 的 rust:python = 800 ms : 840 ms（1.05×）——这个量级的差异
> 在 N=3、`governor=powersave`（变频）条件下**不足以判定为真实差异**，必须用更高的重复次数
> 和显式判定规则来收口，否则博客里写"只快 5%"和写"测不出差异"是两回事。

## 0. 已定口径（用户 2026-10-04 决定）

**所有能力一律 N≥10（含 `sequence.ssr.v1` 与 `fastq.qc.v1`），接受超过 22:30。**
原先的 SSR N=3 运行随即中止（其结论被 N=10 取代），阶段顺序：

| 阶段 | 内容 | 预算 |
| --- | --- | --- |
| 1 | 6 个 fast 能力 N=10（含预热共 11 次/后端） | ≈ 12 min |
| 2 | 粒度解释实验（stats × 3 形状，N=10） | ≈ 6 min |
| 3 | `fastq.qc.v1` N=10（r 腿 704 s/次 → 11 次） | ≈ 2.4 h |
| 4 | `sequence.ssr.v1` N=10（r 腿 1633 s/次 → 11 次） | ≈ 5.0 h |
| 5 | 归档 + README 速查表 + 博客 + 日志 | ≈ 40 min |

余下 §3 的"分轮/精度停止规则"不再适用（一律 N=10 单轮）；保留的披露项：
**每个后端串行测量**（rust 的 10 次跑完才轮到 python/r）可能带入跨后端的频点/热漂移，
因此报告同时记录每后端 10 次原始 wall_ms，并在归档里标注该顺序效应。

## 1. 要回答的问题与判定规则

对每条 (能力 × 后端) 给出：中位数、IQR、CV；对每对 (rust vs 某后端) 给出比值的中位数与
**bootstrap 95% 置信区间**（对原始 wall_ms 重采样，B=10000）。

判定规则（先定规则再看数，避免事后挑选）——**两段式**：

| 条件 | 结论写法 |
| --- | --- |
| 比值 bootstrap 95% CI **完全 ≥ 1.10** | **material**：写"N× 更快（CI 下界 …）" |
| CI 完全 > 1.00 但下界 < 1.10 | **detectable-immaterial**：可分辨但不具实际意义 |
| CI **跨过 1.00** | **within-noise**：写"该输入与该机器上测不出可分辨差异（N=…，CI …）" |

> 规则修正记录（2026-10-04，实测后自我纠正）：最初版本用"2×(两端 CV 之和)"作为噪声带阈值，
> 实测发现它会把一个**一致的 2.4% 差异**判成噪声、把偶发的 15% 差异判成信号——因为
> **离散度不是效应量**。改为上表的两段式（可分辨性 = CI 是否排除 1.0；实质性 = CI 下界是否
> ≥1.10）。CV 仍逐行披露，但不再充当判定阈值。

## 2. 噪声来源与对策

| 来源 | 现状 | 对策 |
| --- | --- | --- |
| CPU 变频（governor=powersave） | 已记录；**SSR 那一行正在该条件下跑** | 保持 powersave 全窗口一致（避免与已归档行混排），用多轮 + 高 N 压制；不切 performance |
| 后端串行测量（A 的全部重复跑完再跑 B） | 存在系统漂移偏差（热、频点、页缓存） | **分轮次**：每轮都完整跑三端，轮次取中位数（轮间交叉，抗漂移） |
| GNU time 量化 1 ms | 已有 | 便宜的输入用更多次重复；ms 级结论标注量化下限 |
| 页缓存 warm/cold 混排 | 已固定 warm（预热 1 次） | 不变；跨缓存状态禁止混排 |
| 窗口内并发负载 | 目前无（构建/工具都停） | 测量期间**不跑任何其它负载**（含 cargo/clippy/归档脚本） |

## 3. 重复次数与停止规则（`N_min=3`，`N_max=15`）

- **Fast 能力**（单轮 < 3 min：stats / pca / venn / enrichment / pdb / variant）：起手 **N=10**。
  若比值 CI 仍不满足 §1 的"可分辨"条件 → 追加第 2 轮（再 N=10），最多 2 轮。
- **Heavy 能力**（fastq.qc、sequence.ssr，r 腿分钟~小时级）：**N=3 / 轮**，最多 2 轮（合计 N=6）。
  理由：这两条的比值是 30×–1000× 量级，精度早已充足；再堆重复只会烧掉时间预算。
  披露时写明每行实际 N。
- 每轮**原始 wall_ms 全部保留**（不用汇总值代替原始数据）。

## 5. 解释性实验：为什么 `sequence.stats` 差异小（把假设变成测量）

固定 ~1 亿碱基，只改**记录粒度**：`1 × 100 Mb`、`20 × 5 Mb`、`100,000 × 1 kb`，三端各 N=5。

预测（模型：比值 ≈ 语言边界穿越次数 × 解释器代价 + 常数项）：
python 随记录数上升明显（每记录 `upper()` + 6 次 `count()` + `replace()` + 建串），
rust 上升平缓（每行一次分配 + 单遍标量循环）→ **比值随粒度拉大**。
若实测不符，则"边界粒度"解释被推翻，博客改写为"两者同为 I/O/内存带宽受限"。
