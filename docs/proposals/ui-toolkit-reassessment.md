# 桌面 UI 工具链再评估：egui（现状）→ Iced（评估中）（2026-10-04，同日修订）

> 触发：桌面应用性能要"好好调一调"；用户要求真正高性能的 Rust GUI，Iced 为主要候选。
> 结论先行：**短期继续用 egui 修短板，同时做一次时间盒 Iced spike（1 页）**；
> spike 达标即按页分批迁移。GPUI 因与 Zed 强绑定而排除；Slint 作为"要 LTS/声明式"时的备选。

## 一、现状事实（含一处口径更正）

- 桌面应用为原生 Rust + egui/eframe 0.35（无 WebView）。
- **规模更正**：此前报的"10.7 万行 UI"是错误的统计口径（`apps/*` 全量计数把一个 **8.5 MB 的中文字体资产**当成行数）。真实规模：
  - Rust 源码 **12,422 行**（主程序 7,759 / 可视化 2,472 / 结构查看器 1,925 / 生成文档快照 266）；
  - 其余为字体与图标资产（NotoSansSC 8.5 MB + 一个 PNG）。
  - 与 egui API 直接耦合的代码行 **1,075 行（约 8.7%）**——即"框架相关"的迁移面很小，其余是业务逻辑。
- **这直接改变结论**：12.4k 行、约 1.1k 行耦合的 UI，**迁移是可行工程量**（此前按 10.7 万行判断为"否决性成本"）。
- 已知性能拖累（用户观察）对应到具体成因：
  1. 大表格每帧全量布局（6 处 `ScrollArea` 未虚拟化）；
  2. 即时模式每帧整棵树重建（egui 架构固有）；
  3. **中日韩文本整形/断行**（我们内嵌 NotoSansSC，egui 的文本栈在这类文本上开销明显）；
  4. SVG/图片预览按帧重绘（无缓存层）。
  其中 1/3/4 正是保留模式 GUI（Iced）天然占优的地方。

## 二、为什么是 Iced（而非 GPUI / 其他）

| 框架 | 关键一手事实 | 判定 |
| --- | --- | --- |
| **Iced** | Elm 风格保留模式；`iced_wgpu`（Vulkan/Metal/DX12/OpenGL/WebGPU）；官方 showcase 是 **COSMIC 桌面（System76）**，COSMIC 已进入 Pop!_OS 与 **Fedora/Arch/NixOS**；crate 文档自述 "experimental software"（API 仍有演进） | **首选**：与我们 wgpu 栈同源、Linux/发行版生态共鸣、保留模式下表格与文本更省 |
| GPUI | 官方页明确与 **Zed 强绑定**，贡献须在 Zed 仓内，无独立发版承诺 | 排除（依赖不稳定） |
| Slint | 1.18、强调 **LTS + 商业支持**、声明式 DSL、嵌入式/桌面/移动 | 备选：若最终要求 LTS 或嵌入式部署再评估（引入 DSL 与许可模型） |
| Xilem/Vello · Floem · Makepad · Dioxus-Native | 研究期 / 编辑器向 / 社区小 / Web 式 | 观察项，不进本轮 |

Iced 对我们四项具体需求的对应：
- **大表格**：`Lazy`（惰性构建，即虚拟化）+ 社区表格控件（表头/排序/列宽）；比 egui 的 `show_rows` 更彻底。
- **中文文本**：cosmic-text 栈（整形/断行/字体回退）质量优于 egui 默认栈，且有文本缓存。
- **SVG/图片**：内建 SVG 支持（resvg 路线）+ 图片控件，配合保留模式缓存，不再每帧重压。
- **3D 结构查看器**：Iced 提供自定义 shader/primitive 扩展点（同为 wgpu），可视化组件可独立于框架演进；最坏情况是保留一块自定义 wgpu 面，而非整页重写。

## 三、行动：时间盒 Iced spike（1 页，5-8 工作日）

**范围**：只迁一页——"结果表格 + 图片/SVG 预览"（最痛的两个点）。

**验收指标（与现有 egui 版对照，Linux 工况）**：
| 指标 | 采集方式 | 期望 |
| --- | --- | --- |
| 空闲 CPU | 空闲 60 s 采样 | ≈0%（不劣于 egui） |
| 启动时间（冷） | 3 次取中位 | ≤ egui 版 |
| 常驻内存（导入 10k 行表格后） | RSS | ≤ egui 版 |
| 10k 行滚动帧时间 | 帧时间 P95 | 明显优于 egui 版（当前全量布局） |
| 中文排版质量 | 目标截图对照 | 优于或持平（不得回退） |
| 二进制体积变化 | strip 前后各测 | 记录，不作为否决项 |

**决策门**：
- 达标 → 按页分批迁移（feature-flag 并存，先结果页再结构页，最后一页才摘 egui）；
- 未达标 → 回 egui 定点优化（虚拟化 6 处 + 文本/SVG 缓存），并把结论写回本文。

## 四、复评触发条件

- Iced 摘掉 "experimental" 自述并给出稳定 API 承诺；
- 或 egui 侧出现无法绕过的限制（Wayland 高 DPI/输入法、超大表格帧率）；
- 或发行版需要"自带桌面工作台"并与基线桌面栈对齐（需与发行版一起评估）。

> 备注：`iced` 与 `COSMIC` 的栈一致意味着——如果将来发行版自带工作台，同一套组件可复用，迁移收益会随时间放大。
