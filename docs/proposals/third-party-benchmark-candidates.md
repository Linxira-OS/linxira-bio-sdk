# 第三方基准候选清单（2026-10-04 调研）

> 目的：把"我们自己跑分"升级为**第三方托管或第三方真值**的对照，避免自证。
> 判定口径：第三方拥有测试定义、真值集或执行基础设施，结果公开可复核。
> 现状承认：**目前没有找到现成的、官方发布的"生物信息学 SDK 横评"**——本清单是可落地的替代路径。

## 一、候选到底是什么（逐项介绍）

### 1. GA4GH Benchmarking / GIAB 高置信集 + hap.py
- **谁维护**：GA4GH Benchmarking 工作组（`ga4gh/benchmarking-tools`）；真值来自 NIST **GIAB（Genome in a Bottle）** 参考材料；评估器 hap.py 由 Illumina 维护。
- **它做什么**：给一份变异检出 VCF，与 NIST 高置信真值**逐位比对**（SNV/INDEL/SV，区分高置信区），输出 TP/FP/FN、precision/recall/F1——这是"结果对不对"的行业标准判据，不是速度。
- **我们怎么参与**：用我们的变异检出能力在 GIAB 样本（如 HG001/HG002）上出 VCF，跑 hap.py 评估；真值集与参考基因组版本必须写死在口径里。无需"申请加入"，产出即可引用。
- **产出**：precision/recall/F1 表 + 可复核的 VCF 与评估日志。

### 2. OpenBenchmarking.org / Phoronix Test Suite（PTS）
- **谁维护**：Phoronix 团队；OpenBenchmarking 是**第三方测试档（test profile）的分发与结果托管平台**（450+ 测试、100+ 套件，且官方明说"未被覆盖的测试可通过其可扩展架构快速新增"）。
- **它做什么**：定义一个可重复的测量（编译/运行脚本 + 解析输出），在任何机器与发行版上跑同一档，结果上传公开库，可横向对比。
- **我们怎么参与**：写一个 test profile 封装 `linxira-bio` CLI + 种子化输入（用我们自己的模拟器生成数据，保证可复现），本机跑通后上传；该类目下已有生信味道的档（如 Timed MrBayes 分析）。
- **产出**：公开可查的结果页 + 可被他人复跑的 profile。

### 3. nf-core / Nextflow 社区流水线
- **谁维护**：nf-core 社区（第三方编写的标准流程）。
- **它做什么**：端到端流水线（fastq → QC → 比对 → 变异 → 注释）的行为与耗时；是**真实用户场景**的参照物。
- **我们怎么参与**：同一输入分别跑 nf-core 流程与我们 CLI 链，做"同输入对照"台账。成本在容器/网络环境。

### 4. Benchmarks Game（语言级基准）
- **谁维护**：Benchmarks Game 社区；题目含 k-nucleotide / fasta 等生物序列味道的微基准。
- **它做什么**：同一算法在不同语言实现的性能对比；支撑"Rust 作为事实高性能语言"的公众叙事。
- **我们怎么参与**：先核对其现行提交入口与许可，再决定是否提供等效实现。

### 5. MLPerf（MLCommons）
- **谁维护**：MLCommons；AI 训练/推理的权威横评。
- **它做什么**：AI 工作负载吞吐/延迟，任务类别固定。
- **我们怎么参与**：**现阶段不适配**——除非 AIVC/开放权重推理成为正式能力，否则无对应任务类别可报。

## 二、"我们自己做，可用吗？"——可以，但分三种成色

| 成色 | 形态 | 第三方成分 | 可否公开引用 |
| --- | --- | --- | --- |
| A（最弱） | 自研输入 + 自研 harness + 自研汇总（现在的 `benchmark.run.v1`） | 无 | 否——只能作内部回归与趋势 |
| B（可用） | **自研 workload + 第三方托管平台**：自写 PTS test profile，结果上传 OpenBenchmarking | 平台方拥有执行框架与公开结果库；第三方机器可复跑 | **可以**——"在第三方平台上可复跑的自研测试" |
| C（最强） | **自研实现 + 第三方真值**：GIAB 真值 + hap.py 评估 | 真值与评估器均为第三方权威 | **可以**——准确性数字有行业可比性 |
| B+C | 自研 profile 同时含"准确性（GIAB）+ 性能（PTS）" | 兼有 | 推荐组合 |

要点：
- **自研本身不是问题，"闭环自证"才是问题**。B/C 两条路都把关键环节交给第三方（执行平台 / 真值），因此结论可外引。
- 自研 workload 的可信度来自**种子化与可复现**（我们已有这个底子：模拟器与字节级复现契约）。
- 命名与口径：profile 命名为中性工具名（如 "Timed Linxira Bio SDK"），把版本、种子、参考基因组/真值版本全部写进结果页与台账；Linux 为唯一正式工况。
- 红线沿用：公开发文仅在用户批准的量化测试完成之后；只写实测能支撑的结论。

## 三、推荐顺序

1. **C：GIAB + hap.py 准确性基准**（先做，投入产出比最高，第三方真值）。
2. **B：PTS test profile 自研并上传**（第二步，拿到第三方托管的公开结果页；顺带服务发行版叙事）。
3. **nf-core 同输入对照**（第三档，环境成本高，按需启动）。
4. Benchmarks Game / MLPerf：观察项，不占排期。
